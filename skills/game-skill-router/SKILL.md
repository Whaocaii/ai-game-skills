# 游戏任务分派

本模块由 Whaocaii 主导设计与维护，使用 AI 辅助编写。当前版本为 0.1.0 工作草稿。按用户的目标与现有项目约束执行；仅使用实际可用的工具。

## 输入

- 要解决的问题与当前可见症状
- 目标平台、引擎、现有实现与本次允许修改的范围

## 工作过程

1. 先把需求写成一个玩家能够观察到的结果。例如把“优化背包”转成“满背包拾取时能明确选择替换物品”。
2. 判断问题主要落在规则、数据、实现还是反馈。只读取与当前问题相连的模块，不按游戏类型一次加载所有模块。
3. 数值问题先读取同级 number-orchestrator；具体功能到 references/catalog.md 找对应模块。跨模块时写清共享的状态和由谁修改。
4. 将工作拆成可独立检查的产出；用户只要方案时交付方案，不自行扩展成代码、部署或付费服务。
5. 根据结果决定是否追加模块。缺少对应模块时说明缺口，使用通用方法处理，不宣称调用了未安装的 Skill。

## 交付

- 任务目标、采用模块和选择理由
- 共享状态、产出顺序与每项完成证据

## 检查

- 每个采用模块都能指向一个当前问题
- 没有把引擎专用实现直接套到其他技术栈

## 使用案例

Godot 塔防中玩家觉得升级炮塔没有感觉。先判断是数值收益不明显还是反馈不清楚，给出最小修改方案。

验收时按上面的检查项判断结果；只读完本文件不代表完成了任务。
