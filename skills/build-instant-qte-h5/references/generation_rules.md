# Template：及时反应·瞬时拦截（QTE）

模板 ID：`qte.instant_intercept@1.0.0`

## 模块定位

当主玩法或局部玩法要求玩家在短暂窗口内完成一次明确操作时调用。本模块负责生成“预警、开窗、输入、判定、反馈、清理”的完整 QTE 节点；它不负责长期养成、叙事分支或关卡外经济。

当 QTE 作为辅助模块时，父玩法拥有长期目标和胜负；QTE 只输出结构化结果事件，由父玩法决定扣血、奖励、剧情分支等后果。

## 输入变量

- `{题材}`
- `{玩家身份与瞬时目标}`
- `{危险或机会来源}`
- `{目标平台与输入设备}`
- `{单局时长}`
- `{QTE 节点数量}`
- `{允许的操作类型}`
- `{成功、失败与评级后果}`
- `{反馈渠道限制}`
- `{额外可访问性要求}`

## 类型核心

玩家必须经历以下闭环：

`危险或机会出现 → 明确预警 → 输入窗口开启 → 玩家执行一次操作 → 唯一判定 → 即时反馈 → 节点清理或进入下一节点`

去掉题材和美术包装后，仍必须存在一个可描述为“在有限窗口内完成正确输入”的可执行挑战。

## 支持的瞬时子型

| 子型 | 典型操作 | 必要判定轴 | 适用题材 |
|---|---|---|---|
| `tap_target` | 点击目标 | 时间 + 目标 | 拍按钮、抓住闪现物、打地鼠 |
| `timing_gate` | 在指示器进入区域时点击 | 时间或逻辑进度 | 挡刀、格挡、精准收线 |
| `swipe_direction` | 向指定方向滑动 | 时间 + 方向 | 闪避、推开、斩击 |
| `swipe_path` | 沿提示路径滑动 | 时间 + 顺序路径 | 划开障碍、连续斩击 |
| `drag_intercept` | 将拦截物拖到交点 | 时间 + 空间重叠 | 接住坠落物、用盾牌挡住攻击 |

连续狂点、长按积蓄和多键组合属于其他 QTE 子模块，不应伪装成“瞬时拦截”。

## 题材转译要求

必须逐项映射：

- 谁或什么产生危险/机会。
- 玩家在观察什么预警。
- 正确目标、方向、路径或拦截区域是什么。
- 为什么玩家必须在此刻行动，不能一直提前按住。
- 成功、普通成功、失败分别改变什么状态。
- 每个结果通过哪些视觉、声音、震动或镜头反馈表达。

每个“好玩点”用以下结构描述：

`通过什么机制 → 让玩家做什么行为 → 产生什么感受 → 用什么运行信号或试玩现象验证`

## 生成硬规则

1. 逻辑时钟必须为单调时钟；不得用帧计数、CSS 动画进度或 DOM 尺寸作为唯一判定真相。
2. 每个 cue 使用固定生命周期：`ready → telegraph → window_open → resolved → recovery/disposed`。
3. 输入必须先映射成语义动作，再进入判定器；模板不得依赖具体键名。
4. 判定至少声明时间、目标、方向、路径、重叠率中的一个轴；多个评级重叠时必须声明优先级和边界归属。
5. `resolved` 后立即关闭输入；迟到回调、双击、多点触控不得改变结果或重复加分。
6. 判定结果先写入状态并发出事件，反馈动画随后消费事件；动画结束回调不能反向决定成功失败。
7. 所有计时器、监听器、指针捕获和临时节点必须在成功、失败、取消与场景离开时统一清理。
8. 切后台默认暂停时间线；恢复后不能暗中消耗窗口。
9. 音频或震动不可用时必须降级到视觉反馈，且不得阻塞游戏逻辑。
10. 难度每阶段优先改变一个主变量：窗口、预警清晰度、目标大小、轨迹速度或干扰物；不得同时恶化全部变量。

## 禁止事项

- 只写“反应要快”“点击正确位置”等自然语言而不提供可判定参数。
- 用素材文件名、DOM ID 或渲染对象充当玩法状态。
- 由不同输入监听器分别结算成功和失败，导致双重结果。
- 成功有反馈、失败无反馈，或玩家不知道错在时机、方向还是目标。
- 随机生成无法避开的 cue，或提示出现时窗口已经开始消耗。
- 把键盘自动重复事件当作长按时长。

## 输出要求

创意 AI 必须输出一个符合 `authoring.schema.json` 的 Authoring Spec，并至少包含：

- 玩家幻想与核心操作。
- 题材元素到威胁、预警、目标、输入和结果的映射。
- cue 生命周期与输入策略。
- 每个 cue 的时间窗、输入要求、评级和状态效果。
- 成功、失败和降级反馈。
- 难度曲线。
- 必需的不变量与黄金测试 ID。

未决策字段必须进入 `decision_status.open`。该数组非空时不得交给 coder。
