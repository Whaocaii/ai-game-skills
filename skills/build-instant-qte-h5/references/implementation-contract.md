# Coder 实现合同

## 先锁定事实

解析上游方案并提取回合顺序、预警、有效动作、控制模型、action pattern、判定窗、提前/超时规则、得失分、结局条件和资源引用。为关键事实保留来源路径，并统一时间单位、输入为语义动作。

不得把未声明规则伪装成原需求。纯表现缺失可按当前设备预算生成候选值并记录来源；胜负、时长、顺序、分数、控制成本或校准参数仍为 open 时必须阻断。Skill 不提供可直接回填的玩法常数。

保留现有项目和 coder 的技术栈。不要为了使用本 Skill 重写框架、接口或用户已有代码。新项目优先使用环境已支持、能可靠交付移动端 2D H5 的最小栈。

在当前用户环境实际编码或打包新 H5 时，若 `/Users/xiezheming/Downloads/framework-1.0.6.zip` 存在且没有更新框架或项目指令覆盖，使用其 `dist/` 作为基线：复制到交付目录，加载生产 UMD `dist/index.umd.production.js`，通过 `window.GameLib` 使用能力，避免再手写一套并行系统。纯 author 模式不引入框架；路径不存在时记录降级原因并继续现有项目栈。

开源参考用于提炼不变量，不等于强制依赖。短局简单 QTE 不要为参考 Phaser/PixiJS 而引入完整引擎；已有引擎时也不要叠加第二套输入、声音或生命周期管理器。

## 唯一运行时真值

把归一后的创意事实固化为只读 `GameSpec`；所有实际数值来自同一 `BalanceProfile`，每项都可追溯到本游戏的 measured 或 inherited 参数。只维护一份 `RuntimeState`，至少覆盖：

`phase、cueId、sequence、openAt、deadlineAt、resolved、outcome、resultEvent`

standalone 游戏可再包含 `score、lives、combo`；embedded QTE 必须把结果事件交给父玩法，父层状态标为 `parent_owned`，不得在模块内复制一套长期分数、生命或胜负。

所有输入、超时和流程推进进入同一个状态转移入口。DOM、Canvas、动画、音频和 HUD 只能读取状态，不得分别保存第二套胜负或倒计时。

## 输入归一化

- 优先使用 Pointer Events，把原始事件转成 `{ action, eventAt, source, pointerId?, position?, phase? }`；判定读取事件发生时间，不读取代码处理到该事件的帧时间。
- 不要同时绑定 `touchstart + mousedown + click` 造成一次操作多次触发。
- press/release 不能因掉帧丢失；同一 pointer 的连续 move 可以合并。忽略键盘自动重复、旧 cue、已消费指针和非法阶段输入。
- 坐标先转换为游戏视口内的归一化坐标。
- 单指游戏必须声明多点触控处理方式，并阻止页面滚动抢走操作。
- 输入只匹配当前最早合法 cue，除非规格明确声明最近目标或显式优先级；后出现 cue 不得抢走属于前一 cue 的输入。

## 诚实控制模型

- `continuous_body`：输入只更新方向或目标，实体按权威速度、加速度或有时长路径移动；不得直接写位置。
- `direct_drag`：权威路径来自 pointer 生命周期，判定使用实际拖拽轨迹与释放状态。
- `discrete_select`：点击只改变选区状态；没有旅行时间时不得把跨区距离当难度。
- `gesture`：识别器从方向、长度、顺序、路径或释放时机产生一次语义动作。

若距离、路径或移动承诺是技能轴，最不利合法起点必须经过真实移动仍可达。输入 buffer/grace 是可选规则；启用时从当前游戏校准合同读取起止、消费、失效和取消条件，不替玩家自动选择或完成动作。

## 确定性时间判定

- 使用封装后的单调时钟，浏览器生产环境取 `performance.now()`。
- 使用绝对 `openAt` 与 `deadlineAt`；未另行声明时，有效区间为 `[openAt, deadlineAt)`。
- `requestAnimationFrame` 和 `setTimeout` 只能触发检查，不得成为判定真值。
- UI 进度由绝对时间推导，不按帧递减。
- 页面隐藏时默认暂停并平移截止时间，除非上游明确要求继续计时。
- 保持“测量时钟”和“动画时钟”分离：反应成绩读取原始单调时间，动画可使用限幅或平滑 delta。
- 后台恢复时重建帧时间基线并丢弃超长 delta，不能让角色瞬移或直接结算。
- 每次时机判定保存 signed error 与 `early/late/exact`；动画速度、内容密度与判定容错各自读取独立参数。

## 单次结算

所有终态只通过一个结算函数进入，例如：

`resolveCue(expectedCueId, outcome, at)`

cue 不匹配或已结算时立即拒绝。输入、超时、动画结束和资源回调必须携带 cue ID 或 sequence；旧回调不得污染新 cue。分数、反馈、埋点与推进副作用只在首次结算后执行一次。

## 反馈顺序

先提交逻辑状态，再派发反馈。动画、音频或震动失败不得回滚或改变结果。关键结果至少以视觉方式表达，且 miss 能指出具体错误。camera、shake、tween 和 hit-stop 不得改变 world position、hitbox、pointer mapping 或 deadline。

## 资源与生命周期

- 图片失败使用可辨识的文字或几何占位；字体回退系统字体；音频失败时静音继续。
- 关键提示不能只依赖颜色、声音或远程资源。
- 资源使用相对路径；关键资源不可用且没有等价降级时阻断交付。
- cue 结算、场景切换、下一结果覆盖旧结果和重开时清理 gesture/buffer、监听、计时器、tween、camera offset、audio fade、粒子和陈旧异步任务，并恢复 canonical transform。
- 处理页面可见性、窗口 resize、移动端 safe area 和音频手势解锁。
- 音频状态至少区分 `locked、loading、ready、failed`；失败时静音继续，输入路径不等待声音播放完成。

## 固定阶段顺序

每帧保持：

`采集输入 → 归一化语义动作 → 更新判定状态 → 更新场景 → 渲染反馈 → 清理 pressed/released 边沿态`

系统不得任意穿插改变顺序。资源未就绪时只运行加载界面，不进入正式计时；监听器必须在重开或场景销毁时成对解绑。

## 最小测试表面

优先做黑盒浏览器测试。如果边界判定无法稳定自动化，在仅测试模式下暴露最小适配器，例如 `globalThis.__QTE_TEST__`：

- `reset(seed?)`：重置并为 QA 固定 run seed；普通正式对局按 `runtime_variation_policy` 生成并记录新 seed。
- `advance(ms)`：推进测试时钟，同时走正式超时路径。
- `act(action)`：通过正式输入入口提交语义动作。
- `snapshot()`：只读返回阶段、cue、窗口、结果，以及当前 scope 适用的模块状态。

embedded 模式的 `snapshot()` 可省略父层分数，但必须返回已发出的 `resultEvent`。

测试钩子不得绕过正式判定或存在于默认生产交互中。

## 阻断条件

以下任一项存在时，不得宣称完成：

- 核心上游规则无法解析或仍有胜负冲突。
- 存在多套时钟、重复状态或绕开统一结算的路径。
- 边界、竞争或 resolved-once 测试不稳定。
- 移动端输入重复、失效或坐标错位。
- 关键资源失败会白屏、卡死或使玩法无法理解。
- 启动存在未捕获异常，或关键路径无法完成。
- 无输入、提前占位或随机输入能取得最高评级或稳定完成。
- 声明为连续移动却在运行时直接瞬移，或声明为瞬时选区却把距离当作难度。
- 相邻阶段只有数值变化，高峰只全面加速，或恢复段只有等待。
